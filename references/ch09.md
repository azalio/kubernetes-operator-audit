# Chapter 9 — Cross-chapter consistency

## Essence
Consolidate chapter findings across architecture, implementation, packaging and lifecycle maintenance. Verify that contracts and evidence agree across passes. Repeated observations must not inflate finding counts or turn SDK-specific details into universal requirements.

## Routing checks

## B09-01 — Identify controller and capability boundary
Applies: all operator audits. Evidence: operand list, architecture, implementation language and documented features. Fail: auditor excludes a non-Go/non-SDK operator or assumes every operator promises Auto Pilot. Remedy: inventory actual behavior and route to B01-01 through B01-05; score claims against evidence, not toolkit labels.
## B09-02 — Identify API and access surface
Applies: all operators; CRD checks only where CRDs exist. Evidence: resource kinds, schema versus CR examples, installation namespace, watch reach and access bindings. Fail: CR and CRD are confused or namespace scope is inferred from only one artifact. Remedy: route schema checks to B03-01 and scope/RBAC to B02-02 and B04-06, without duplicating findings.
## B09-03 — Trace executable control and reporting paths
Applies: all controller implementations. Evidence: actual entrypoint, queue/reconcile equivalent, resource mutation, status, metrics and probes. Fail: audit checks only scaffolding or treats event history as authoritative current state. Remedy: route convergence to B03-02/B03-03 and B04-04/B04-05; diagnostics/HA to chapter 5. Language-equivalent code paths count.
## B09-04 — Select deployment/distribution route
Applies: all installations, OLM checks conditionally. Evidence: supported deployment instructions and release artifacts. Fail: lack of OLM/OperatorHub is called a defect, or bundle publication is accepted as runtime proof. Remedy: apply chapter 6 to actual deployments and chapter 7 only to claimed bundle/catalog integrations.
## B09-05 — Separate release, API and storage versions
Applies: evolving projects. Evidence: release metadata, served/storage API versions, conversion implementation and compatibility policy. Fail: one version number or a new CSV is assumed to prove all migration safety. Remedy: route to B08-01 through B08-07 and distinguish distribution upgrade paths from data/API conversion.

## Applicability and cautions
Record a defect once and retain every affected failed control; routing checks do not create extra severity for the same bug. Conditions are not boolean-only; cluster-scoped controllers can run namespaced Pods; CRDs need not be Go-generated. Inspect actual image build inputs and packaged assets. Generic OLM assurances are not a supported rollback guarantee. Check support windows and release cadence against the project's current policy. Treat channels as catalog/distribution concepts. Resolve inconsistent chapter conclusions using the cited implementation and version-specific documentation.
